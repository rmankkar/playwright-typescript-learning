
# Project Instructions – Playwright TypeScript Learning Framework

## Project Objective

Build a professional, scalable Playwright + TypeScript automation framework while treating the repository as a practical learning resource.

The user is an experienced QA professional learning Playwright and TypeScript.

## Mandatory Rules

1. Never create, modify, rename or delete files without explicit approval.
2. Explain the purpose of every proposed file and folder before creating it.
3. Work incrementally, one file at a time.
4. Include meaningful educational comments in all source and configuration files.
5. Explain important TypeScript and Playwright concepts during implementation.
6. Validate changes and explain execution results.
7. Never silently overwrite existing implementation.
8. Keep documentation synchronized with actual implementation.

## Teaching Style

- Use simple, clear English.
- Explain concepts with practical examples.
- Relate Playwright concepts to Selenium/UFT when useful.
- Explain architectural decisions and alternatives.
- Avoid unnecessary theoretical explanations.

## Coding Standards

- TypeScript strict mode.
- Playwright Test framework.
- Async/await.
- Reliable locator strategies.
- Web-first assertions.
- Reusable and maintainable components.
- No unnecessary fixed waits.
- No hardcoded credentials or secrets.
